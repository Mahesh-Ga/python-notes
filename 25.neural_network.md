## What is a Neural Network?

A **Neural Network** is a computational model inspired by the way biological neural networks in the human brain process information. It is a collection of connected units or nodes called **artificial neurons**, organized in layers, which loosely mimic the neurons in a biological brain.

Neural Networks are the foundation of **Deep Learning** and are used to recognize patterns, classify data, make predictions, and solve complex problems that are difficult to solve using traditional rule-based programming — such as image recognition, speech recognition, and natural language processing.

In simple words: a Neural Network takes an input, passes it through one or more layers of interconnected nodes (each of which performs a small computation), and produces an output. During training, the network **learns** by adjusting the strength of connections between nodes so that its output gets closer to the desired result.

---

## Biological Neuron vs Artificial Neuron

| Biological Neuron | Artificial Neuron |
|---|---|
| Dendrites receive signals | Inputs (`x1, x2, ..., xn`) receive data |
| Cell body (soma) processes signals | Summation function combines weighted inputs |
| Axon carries output signal | Activation function produces output |
| Synapse strength = signal importance | Weight (`w`) = importance of an input |
| Neuron fires if signal exceeds threshold | Activation function fires if weighted sum exceeds a threshold/bias |

The **Perceptron**, introduced by Frank Rosenblatt(father of deep learning) in 1958, was the first mathematical model of an artificial neuron and is the basic building block of a neural network.

---

## Basic Structure of a Neural Network

A typical neural network consists of **three types of layers**:

1. **Input Layer** — receives the raw input features (e.g., pixel values of an image, words of a sentence). It does not perform any computation; it simply passes data to the next layer.
2. **Hidden Layer(s)** — layers between the input and output layers where the actual computation happens. A network can have one hidden layer (**shallow network**) or many hidden layers (**deep network**, hence "Deep Learning").
3. **Output Layer** — produces the final result, such as a class label (classification) or a continuous value (regression).

```
Input Layer        Hidden Layer(s)        Output Layer
   (x1)  ─────┐        ┌──►(h1)──┐
   (x2)  ─────┼──►  ───┤         ├──►  ───►  (y)
   (x3)  ─────┘        └──►(h2)──┘
```

Each connection between two neurons has an associated **weight**, and each neuron (except input) has an associated **bias**. Together, weights and biases are the **parameters** the network learns during training.

---

## How a Single Neuron Works

Every artificial neuron performs two steps:

### Step 1: Weighted Sum (Linear Combination)

```
z = (w1*x1 + w2*x2 + ... + wn*xn) + b
```

Where:
- `x1, x2, ..., xn` → input values
- `w1, w2, ..., wn` → weights associated with each input
- `b` → bias term (allows shifting the activation threshold)
- `z` → weighted sum (also called the **pre-activation** value)

### Step 2: Activation Function

```
output = f(z)
```

The activation function `f` introduces **non-linearity** into the network. Without it, no matter how many layers are stacked, the network would behave like a single linear function — unable to learn complex patterns.

---

## Activation Functions

Activation functions decide whether a neuron should be "activated" or not, based on its weighted input.

| Activation Function | Formula | Range | Typical Use |
|---|---|---|---|
| **Sigmoid** | `f(z) = 1 / (1 + e^-z)` | (0, 1) | Binary classification output layer |
| **Tanh** | `f(z) = (e^z - e^-z) / (e^z + e^-z)` | (-1, 1) | Hidden layers (zero-centered, better than sigmoid) |
| **ReLU** (Rectified Linear Unit) | `f(z) = max(0, z)` | [0, ∞) | Most common choice for hidden layers |
| **Leaky ReLU** | `f(z) = z if z>0 else 0.01z` | (-∞, ∞) | Fixes "dying ReLU" problem |
| **Softmax** | `f(z_i) = e^(z_i) / Σ e^(z_j)` | (0, 1), sums to 1 | Multi-class classification output layer |

**Note:** ReLU is the most widely used activation function in hidden layers because it is computationally cheap and helps mitigate the **vanishing gradient problem**, which was common with Sigmoid and Tanh in deep networks.

---

## Forward Propagation

**Forward Propagation** is the process of passing input data through the network, layer by layer, to generate an output/prediction.

1. Input values enter the input layer.
2. Each hidden layer computes a weighted sum of its inputs, adds a bias, and applies an activation function.
3. This process repeats until the output layer produces the final prediction.

```
Layer 1: z1 = W1·X + b1        a1 = f(z1)
Layer 2: z2 = W2·a1 + b2       a2 = f(z2)
Output:  z3 = W3·a2 + b3       y_pred = f(z3)
```

---

## Loss Function (Cost Function)

The **Loss Function** measures how far the network's prediction (`y_pred`) is from the actual target value (`y_actual`). The goal of training is to **minimize** this loss.

| Loss Function | Formula | Used For |
|---|---|---|
| **Mean Squared Error (MSE)** | `(1/n) Σ (y_actual - y_pred)^2` | Regression problems |
| **Binary Cross-Entropy** | `-[y·log(p) + (1-y)·log(1-p)]` | Binary classification |
| **Categorical Cross-Entropy** | `-Σ y_i · log(p_i)` | Multi-class classification |

## Gradient Descent

**Gradient Descent** is an **optimization algorithm** used to minimize the loss function by iteratively adjusting the network's weights and biases in the direction that reduces the error the most.

### Intuition

Imagine you are standing on a hilly surface (the **loss landscape**) in thick fog, and your goal is to reach the lowest point (**minimum loss**) without being able to see the whole terrain. The only thing you can sense is the **slope** under your feet. A sensible strategy is to take a small step in the direction that goes downhill the fastest, then repeat. That is exactly what Gradient Descent does — the "slope" is the **gradient** (derivative) of the loss function, and the network keeps stepping downhill until it reaches (close to) the minimum.

### The Formula

For every weight `w` in the network:

```
w_new = w_old - learning_rate * (∂Loss / ∂w)
```

Where:
- `∂Loss / ∂w` → the **gradient** — how much the loss changes when `w` changes. It tells us the **direction of steepest ascent**, so we move in the **opposite** direction (hence the minus sign) to decrease the loss.
- `learning_rate` (α) → a small positive number that controls **how big a step** to take in that direction.

This same update rule is applied to every weight and bias in the network, using the gradients computed during **Backpropagation** (see below).

### Role of the Learning Rate

The learning rate is one of the most important hyperparameters to get right:

| Learning Rate | Effect |
|---|---|
| **Too small** | Training converges very slowly, may get stuck before reaching a good minimum, wastes compute |
| **Too large** | Updates overshoot the minimum, loss can bounce around or even diverge (increase instead of decrease) |
| **Just right** | Loss decreases smoothly and steadily until it converges to a minimum |

In practice, techniques like **learning rate schedules** (gradually decreasing the learning rate over training) or **adaptive optimizers** (Adam, RMSprop) are used instead of a single fixed value.

### Types of Gradient Descent

| Variant | How much data used per update | Description |
|---|---|---|
| **Batch Gradient Descent** | Entire training dataset | Computes the gradient using **all** training examples before making one weight update — accurate and stable, but slow and memory-heavy on large datasets |
| **Stochastic Gradient Descent (SGD)** | One example | Updates weights after **every single** training example — very fast per step, but the path to the minimum is noisy/zig-zagging |
| **Mini-Batch Gradient Descent** | A small batch (e.g., 32, 64, 128) | Updates weights after each small batch of examples — the most widely used approach in practice, balancing the stability of Batch GD with the speed of SGD |

### Common Challenges in Gradient Descent

- **Local Minima** — the algorithm can get stuck in a valley that isn't the lowest point overall (the **global minimum**).
- **Saddle Points** — flat regions where the gradient is close to zero in some directions but not a true minimum, which can slow down learning significantly.
- **Vanishing/Exploding Gradients** — in deep networks, gradients can become extremely small (vanish) or extremely large (explode) as they are backpropagated through many layers, making updates ineffective or unstable.
- **Choosing the Learning Rate** — as covered above, this single hyperparameter can make or break training.

### Optimizers Built on Gradient Descent

An **optimizer** is the rule that decides **how to update the weights** once backpropagation has given us the gradients. Plain gradient descent uses the same fixed step for every weight and only looks at the current gradient. That causes problems: it zig-zags in narrow valleys, crawls across flat areas, and one learning rate doesn't suit every weight.

Modern optimizers fix this using two ideas:
1. **Momentum** — remember the direction you've been moving in and keep going that way (fixes zig-zagging and slow progress on flat regions)
2. **Adaptive learning rate** — give each weight its own step size based on how big its gradients have been (fixes "one learning rate for everything")

Notation below: `g` = gradient of loss w.r.t. a weight, `lr` = learning rate, `ε` = tiny number (like 1e-8) to avoid dividing by zero.

#### 1. SGD (plain / mini-batch)

```
w = w - lr * g
```

- Simplest, just the basic gradient descent rule applied on mini-batches
- Noisy and slow in ravines, very sensitive to learning rate
- Still used (with momentum) in computer vision because it often **generalizes better** than Adam when tuned well

#### 2. SGD with Momentum

```
v = β * v + g          # β usually 0.9
w = w - lr * v
```

- `v` is a running "velocity", a decaying sum of past gradients
- Think of a ball rolling downhill: it builds speed in a consistent direction and doesn't get stopped by small bumps
- Oscillations that flip direction cancel out, consistent directions add up → faster and smoother convergence
- **Nesterov Momentum (NAG)** is a small tweak: compute the gradient at the "look-ahead" position (where momentum is about to take you), so it corrects itself earlier and overshoots less

#### 3. Adagrad (Adaptive Gradient)

```
G = G + g²
w = w - lr * g / (√G + ε)
```

- Each weight gets its own effective learning rate: weights with big/frequent gradients get smaller steps, rare ones get bigger steps
- Good for **sparse data** (NLP word features, recommendation)
- Problem: `G` only ever grows, so the learning rate keeps shrinking until learning basically stops

#### 4. RMSprop

```
s = β * s + (1 - β) * g²     # β usually 0.9
w = w - lr * g / (√s + ε)
```

- Same idea as Adagrad, but uses a **moving average** of squared gradients instead of a sum, so the learning rate doesn't decay to zero
- Works well for RNNs and non-stationary problems

#### 5. Adam (Adaptive Moment Estimation)

```
m = β1 * m + (1 - β1) * g        # 1st moment: momentum (mean of gradients)
v = β2 * v + (1 - β2) * g²       # 2nd moment: RMSprop part (mean of squared gradients)

m_hat = m / (1 - β1^t)           # bias correction (m, v start at 0,
v_hat = v / (1 - β2^t)           # so early values are too small)

w = w - lr * m_hat / (√v_hat + ε)
```

- Defaults: `lr = 0.001`, `β1 = 0.9`, `β2 = 0.999`, `ε = 1e-8`
- **Momentum + RMSprop combined**, with bias correction for the first few steps
- Fast, stable, works out of the box with little tuning → the default choice for most deep learning
- Downside: uses 2 extra values per weight (more memory), and can generalize slightly worse than tuned SGD on some vision tasks

#### 6. AdamW (Adam with decoupled Weight Decay)

- In plain Adam, L2 regularization gets mixed into the adaptive scaling, so it doesn't regularize properly
- AdamW applies weight decay **directly to the weights**, separate from the gradient update:
  ```
  w = w - lr * (m_hat / (√v_hat + ε) + weight_decay * w)
  ```
- This is the **standard optimizer for training Transformers / LLMs** (BERT, GPT, fine-tuning)

#### Comparison Table

| Optimizer | Momentum? | Per-weight adaptive LR? | Best for / notes |
|---|---|---|---|
| **SGD** | No | No | Baseline, simple problems |
| **SGD + Momentum** | Yes | No | CNNs / vision when well tuned, good generalization |
| **Adagrad** | No | Yes (sum, decays forever) | Sparse features; LR dies out over time |
| **RMSprop** | No | Yes (moving average) | RNNs, non-stationary problems |
| **Adam** | Yes | Yes | General default, fast convergence |
| **AdamW** | Yes | Yes | Transformers, LLMs, fine-tuning |

#### Which One to Pick?

- Not sure → **Adam** (lr = 0.001)
- Transformers / LLMs / fine-tuning → **AdamW** with a warmup + decay learning rate schedule
- CNNs where you want the best final accuracy and can spend time tuning → **SGD + Momentum** (0.9) with a learning rate schedule
- Sparse features → Adagrad or Adam

#### Usage in Code

```python
# Keras
from tensorflow.keras.optimizers import SGD, Adam, AdamW
model.compile(optimizer=Adam(learning_rate=0.001), loss="binary_crossentropy")
model.compile(optimizer=SGD(learning_rate=0.01, momentum=0.9, nesterov=True), loss="mse")

# PyTorch
import torch
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)

for x, y in loader:
    optimizer.zero_grad()          # clear old gradients
    loss = loss_fn(model(x), y)
    loss.backward()                # backprop: compute gradients
    optimizer.step()               # optimizer: update weights
```

#### Interview One-Liners

- **Optimizer vs Backpropagation:** backprop computes the gradients, the optimizer decides how to use them to update the weights
- **Optimizer vs Loss function:** the loss measures how wrong the model is, the optimizer is how we reduce it
- **Why Adam over SGD?** Adam gives each weight its own adaptive step size and uses momentum, so it converges faster with less tuning
- **Why bias correction in Adam?** `m` and `v` start at 0, so early averages are biased toward 0; dividing by `(1 - β^t)` fixes that in the first steps
- **Adam vs AdamW?** AdamW separates weight decay from the gradient update, so regularization actually works as intended. It's the standard for Transformers

### Simple Gradient Descent Example in Python

```python
# Minimizing a simple function f(x) = x^2 using Gradient Descent
x = 10.0            # initial guess
learning_rate = 0.1
epochs = 20

for i in range(epochs):
    gradient = 2 * x          # derivative of x^2 is 2x
    x = x - learning_rate * gradient
    print(f"Epoch {i+1}: x = {x:.4f}")

# x keeps moving closer to 0, which is the minimum of f(x) = x^2
```

## Backpropagation

**Backpropagation** (short for "backward propagation of errors") is the algorithm used to train neural networks. It calculates how much each weight contributed to the error and updates the weights to reduce that error.

**How it works, step by step:**

1. Perform **forward propagation** to get the predicted output.
2. Calculate the **loss** using a loss function.
3. Compute the **gradient** (derivative) of the loss with respect to each weight, moving backward from the output layer to the input layer, using the **chain rule** of calculus.
4. Update each weight using **Gradient Descent** (see above):

```
w_new = w_old - learning_rate * (∂Loss / ∂w)
```

This process is repeated over many iterations (**epochs**) until the loss becomes acceptably small. In short: **Backpropagation** computes the gradients, and **Gradient Descent** uses those gradients to actually update the weights.

Neural networks come in many architectures, each suited to a different kind of data or problem — the same underlying building blocks (neurons, weights, activation functions, backpropagation) arranged with a different **inductive bias**.

|---|---|---|

## Overfitting and Regularization Techniques

**Overfitting** occurs when a neural network learns the training data too well — including its noise — and performs poorly on unseen/test data.

**Regularization** is any technique that makes it harder for the model to memorize the training data, so it is pushed to learn general patterns instead. The trade-off: training accuracy usually drops a little, but validation/test accuracy goes up.

### Underfitting vs Overfitting (Bias vs Variance)

| | Underfitting | Good fit | Overfitting |
|---|---|---|---|
| Training loss | High | Low | Very low |
| Validation loss | High | Low | High (and rising) |
| Problem | **High bias** — model too simple | — | **High variance** — model too complex / memorizing |
| Fix | Bigger model, train longer, better features, *less* regularization | — | More data, *more* regularization, smaller model |

**How to spot overfitting:** training loss keeps going down while validation loss stops improving and starts going back up. The gap between the two curves is the overfitting.

### Summary Table

| Technique | How it Helps |
|---|---|
| **Dropout** | Randomly "drops" (deactivates) a fraction of neurons during training, forcing the network to not rely too heavily on specific neurons |
| **L1/L2 Regularization** | Adds a penalty term to the loss function based on the magnitude of weights, discouraging overly large weights |
| **Batch Normalization** | Normalizes the output of a layer before passing it to the next, stabilizing and speeding up training |
| **Early Stopping** | Stops training once validation loss stops improving, before the model starts overfitting |
| **Data Augmentation** | Artificially increases training data variety (e.g., rotating/flipping images) so the model generalizes better |

### 1. L2 Regularization (Ridge / Weight Decay)

```
Loss_total = Loss + λ * Σ w²
```

- Adds the **sum of squared weights** to the loss, so big weights get penalized
- `λ` (lambda) controls the strength: too high → underfitting, too low → no effect. Typical values: 1e-4 to 1e-2
- Effect: weights shrink toward zero but **rarely become exactly zero**, so all features still contribute a little
- Why it helps: big weights mean the model reacts strongly to tiny input changes (spiky, memorizing function). Small weights → smoother function → generalizes better
- Called **weight decay** because the update becomes `w = w - lr * (g + 2λw)`, so each step shrinks the weight a bit. (With Adam, use **AdamW** for this to work properly — see Optimizers above)

### 2. L1 Regularization (Lasso)

```
Loss_total = Loss + λ * Σ |w|
```

- Adds the **sum of absolute weights**
- Effect: pushes many weights to **exactly zero** → a **sparse** model, which works like automatic feature selection
- Useful when you think only a few input features actually matter

**L1 vs L2:**

| | L1 | L2 |
|---|---|---|
| Penalty | `λ Σ |w|` | `λ Σ w²` |
| Weights become | Many exactly 0 (sparse) | Small but non-zero |
| Use for | Feature selection, sparse models | General default in neural nets |
| Combined | **Elastic Net** = L1 + L2 | |

### 3. Dropout

- During training, each neuron in a layer is turned off with probability `p` (e.g., 0.2–0.5) on every forward pass
- Each mini-batch effectively trains a different "thinned" network, so it works like training an **ensemble** of many networks that share weights
- Neurons can't rely on specific other neurons being present (prevents **co-adaptation**), so each one has to learn useful features on its own
- **At inference, dropout is turned off** and all neurons are used. To keep output scale the same, modern frameworks use **inverted dropout**: scale the kept activations by `1/(1-p)` during training, so nothing changes at test time
- That's why you must call `model.eval()` in PyTorch before inference (Keras handles it automatically with `training=False`)
- Typical: 0.5 for big dense layers, 0.1–0.3 for others, ~0.1 in Transformers

#### Intuition

Think of a team where one person always does the hard work. If that person is out sick, the team fails. If people are randomly absent every day, everyone has to learn to do the job, so the team becomes robust. Dropout does the same to neurons: no single neuron (or small group) can carry the prediction, so knowledge gets spread across the network.

#### How It Works Step by Step

For a layer with activations `a` and dropout rate `p` (probability of **dropping**):

```
Training:
  mask = random values, each 1 with probability (1-p), 0 with probability p
  a_out = (a * mask) / (1 - p)      # inverted dropout: scale up the survivors

Inference:
  a_out = a                          # no dropout, no scaling
```

**Worked example** with `p = 0.5`:

```
activations a     = [2.0, 4.0, 1.0, 3.0]
random mask       = [1,   0,   1,   0  ]
a * mask          = [2.0, 0.0, 1.0, 0.0]
÷ (1 - 0.5)       = [4.0, 0.0, 2.0, 0.0]   ← output during training
```

**Why scale by `1/(1-p)`?** With `p = 0.5`, only half the neurons fire, so the next layer would get roughly half the total signal it gets at test time. Scaling the survivors by 2 keeps the **expected value** the same in training and inference, so the model doesn't have to be changed at test time.

(The original 2014 paper did the opposite: no scaling during training, multiply weights by `(1-p)` at test time. Same result, but inverted dropout is what Keras/PyTorch use because inference stays untouched.)

#### Watch Out: `p` Means Different Things

- In **Keras** `Dropout(0.3)` and **PyTorch** `nn.Dropout(p=0.3)`, the value is the fraction **dropped**
- In the original paper and old TensorFlow 1.x `keep_prob`, it was the fraction **kept**
- So `Dropout(0.2)` drops 20%, keeps 80%

#### Where to Put Dropout

- After the activation of **fully connected (Dense) layers**, especially large ones (that's where most parameters, and most overfitting, live)
- Usually **not on the output layer**
- Rarely on the input layer; if used, keep it small (≈0.1–0.2)
- In **CNNs**, use it mostly in the dense layers at the end; inside conv layers, plain dropout works poorly because neighbouring pixels are strongly correlated, so use **Spatial Dropout** instead
- In **Transformers**: after attention weights, after each sub-layer (before the residual add), and on embeddings

#### Variants

| Variant | What it drops | Used in |
|---|---|---|
| **Standard Dropout** | Individual neurons | Dense layers |
| **Spatial Dropout (Dropout2D)** | Whole feature maps / channels | CNNs |
| **DropConnect** | Individual weights (connections), not neurons | Research, some dense nets |
| **Recurrent / Variational Dropout** | Same mask at every time step | RNNs / LSTMs (a new mask per step breaks memory) |
| **Attention Dropout** | Entries of the attention weight matrix | Transformers |
| **DropPath / Stochastic Depth** | Whole residual blocks | ResNets, Vision Transformers |
| **Monte Carlo (MC) Dropout** | Keeps dropout **on at inference**, runs many forward passes | Uncertainty estimation |

**MC Dropout** in one line: run the same input through the model, say, 50 times with dropout on. The **mean** of the predictions is the answer, and the **spread (variance)** tells you how uncertain the model is. Useful in medical / high-risk predictions.

#### Dropout and Training Behaviour

- Training loss will be **higher and noisier** than without dropout — that's expected, it's the model being handicapped on purpose
- It's normal to see **validation loss lower than training loss** with dropout, because validation runs with dropout off
- Training usually needs **more epochs** to converge
- Too much dropout → **underfitting** (the model can't learn enough)

#### Dropout with Batch Normalization

- Mixing them in the same block can hurt: dropout changes the variance of activations between training and inference, which confuses BatchNorm's running statistics ("variance shift")
- Common practice: use BatchNorm in conv layers, and put dropout **only after the last BatchNorm**, in the final dense layers. Or just use one of the two

#### When Not to Use Dropout

- Small models or small datasets where the model is **underfitting** already
- Very large pre-training runs with huge data (many modern LLMs train with dropout = 0, since with that much data overfitting isn't the problem). It's often turned back on (~0.1) for **fine-tuning** on small datasets

#### Dropout in Code

```python
# Keras
from tensorflow.keras import layers
model = tf.keras.Sequential([
    layers.Conv2D(32, 3, activation="relu"),
    layers.SpatialDropout2D(0.2),       # drops whole channels
    layers.Flatten(),
    layers.Dense(256, activation="relu"),
    layers.Dropout(0.5),                 # drops 50% of neurons
    layers.Dense(10, activation="softmax"),
])
model(x, training=True)    # dropout active
model(x, training=False)   # dropout off (what predict() uses)

# PyTorch
import torch
import torch.nn as nn
drop = nn.Dropout(p=0.5)
x = torch.tensor([2.0, 4.0, 1.0, 3.0])

drop.train()
print(drop(x))   # e.g. tensor([4., 0., 2., 0.]) — random each call
drop.eval()
print(drop(x))   # tensor([2., 4., 1., 3.]) — unchanged

# MC Dropout: keep dropout on at inference for uncertainty
model.train()
preds = torch.stack([model(x) for _ in range(50)])
mean, uncertainty = preds.mean(0), preds.std(0)
```

#### Dropout From Scratch (NumPy)

```python
import numpy as np

def dropout(a, p, training=True):
    if not training or p == 0:
        return a
    mask = (np.random.rand(*a.shape) > p).astype(a.dtype)   # 1 = keep
    return a * mask / (1 - p)

a = np.array([2.0, 4.0, 1.0, 3.0])
print(dropout(a, p=0.5))                  # e.g. [4. 0. 2. 0.]
print(dropout(a, p=0.5, training=False))  # [2. 4. 1. 3.]
```

#### Dropout Interview Questions

- **What is dropout?** Randomly turning off a fraction `p` of neurons on each training step so the network can't rely on any single neuron
- **Why does it reduce overfitting?** It prevents co-adaptation and acts like averaging an ensemble of exponentially many thinned networks that share weights
- **What happens at test time?** Dropout is off; all neurons are used
- **What is inverted dropout?** Scaling kept activations by `1/(1-p)` during training so the expected output matches inference and nothing has to change at test time
- **Is `p` the keep or drop probability?** In Keras/PyTorch it's the drop probability
- **Why is my validation loss lower than training loss?** Dropout is on during training (handicapped) and off during validation
- **Dropout in CNNs / RNNs?** CNNs → Spatial Dropout (whole channels); RNNs → same mask across time steps (variational dropout)
- **What is MC Dropout?** Keeping dropout on at inference and averaging many passes; the variance gives an uncertainty estimate
- **Dropout vs L2?** L2 shrinks weights through the loss; dropout adds noise to the architecture during training. They're often used together

### 4. Early Stopping

- Track validation loss after every epoch, stop when it hasn't improved for `patience` epochs, and restore the best weights
- Free and simple, almost always worth using
- Works as regularization because it stops the model before it has time to memorize the noise

### 5. Data Augmentation

- Create new training examples from existing ones by applying changes that don't change the label
- Images: flip, rotate, crop, zoom, color jitter, Cutout, Mixup
- Text: synonym replacement, back-translation, random word deletion
- Audio: add noise, shift time, change pitch
- More (varied) data is the **most reliable** cure for overfitting; augmentation is the cheap way to get it

### 6. Batch Normalization

- Normalizes each layer's inputs over the mini-batch (mean 0, variance 1), then applies a learnable scale and shift
- Main purpose is **faster and more stable training**, but it has a **mild regularization** side effect, because each batch's mean/variance adds a bit of noise
- Like dropout, it behaves differently in training (batch stats) vs inference (running averages) → again why `model.eval()` matters
- Transformers use **Layer Normalization** instead (normalizes across features, not across the batch)

#### The Problem It Solves

We already normalize (scale) the **input** features before training, because gradient descent works much better when inputs are on a similar scale with mean around 0. But inside the network, each layer's output becomes the next layer's input, and those values can drift to any scale, and they keep changing as earlier layers' weights get updated. So every layer is trying to learn on top of a moving target.

BatchNorm applies the same "normalize the inputs" idea **inside** the network, at every layer where you add it.

#### How It Works Step by Step

For each feature (neuron), over a mini-batch of `m` examples:

```
1. Batch mean:      μ = (1/m) Σ x_i
2. Batch variance:  σ² = (1/m) Σ (x_i - μ)²
3. Normalize:       x̂_i = (x_i - μ) / √(σ² + ε)          # mean 0, variance 1
4. Scale and shift: y_i = γ * x̂_i + β                    # γ, β are learned
```

- `ε` is a tiny number (like 1e-5) so we never divide by zero
- `γ` (gamma, scale) starts at 1 and `β` (beta, shift) starts at 0, and both are **learned by backprop** like normal weights

**Why the learnable γ and β?** Forcing every layer to exactly mean 0 / variance 1 could limit what the network can represent (e.g., squashing everything into the linear middle part of a sigmoid). With γ and β the network can pick whatever scale and shift works best, and can even undo the normalization completely (`γ = σ`, `β = μ`) if that's what's needed.

**Worked example** — one neuron, batch of 4:

```
x            = [2, 4, 6, 8]
μ            = 5
σ²           = ((−3)² + (−1)² + 1² + 3²) / 4 = 5     → σ ≈ 2.236
x̂ = (x−μ)/σ = [−1.34, −0.45, 0.45, 1.34]
y = 1·x̂ + 0 = [−1.34, −0.45, 0.45, 1.34]             (γ=1, β=0 at start)
```

#### Training vs Inference

At inference you might predict a **single example**, so there's no batch to compute a mean/variance from. And you want the same input to always give the same output, no matter what else is in the batch. So:

- **During training:** use the current mini-batch's `μ` and `σ²`, and also keep a **running (moving) average** of them:
  ```
  running_mean = momentum * running_mean + (1 − momentum) * μ_batch   # Keras style, momentum = 0.99
  ```
- **During inference:** use the stored `running_mean` and `running_var` instead of batch stats. Output is now deterministic

⚠️ **The momentum value is defined differently in the two frameworks**:
- Keras `momentum=0.99` → weight on the **old** running value
- PyTorch `momentum=0.1` → weight on the **new** batch value
- Both mean the same thing: "mostly keep the old average, add a little of the new batch"

#### Parameters per BatchNorm Layer

For each feature/channel there are **4 numbers**:

| Parameter | Learned by backprop? |
|---|---|
| `γ` (scale) | Yes — trainable |
| `β` (shift) | Yes — trainable |
| `running_mean` | No — updated by moving average |
| `running_var` | No — updated by moving average |

That's why `model.summary()` in Keras shows BatchNorm with some **non-trainable params**.

#### BatchNorm in CNNs

- In dense layers: statistics are computed **per neuron**, across the batch
- In conv layers: statistics are computed **per channel**, across the batch **and** all spatial positions (height × width). So one `γ, β` pair per channel, not per pixel
- `BatchNorm1d` (dense / sequences), `BatchNorm2d` (images) in PyTorch; Keras `BatchNormalization()` handles both

#### Why It Helps

| Benefit | Why |
|---|---|
| **Faster training** | Can use **much higher learning rates** without diverging |
| **More stable training** | Activations stay in a reasonable range, reducing vanishing/exploding gradients |
| **Less sensitive to weight initialization** | Bad init gets corrected by normalization |
| **Mild regularization** | Each example's output depends a little on the other examples in its batch → adds noise, similar in spirit to dropout |
| **Makes deep nets trainable** | A big reason very deep CNNs (ResNets) became practical |

**Why does it actually work?** The original 2015 paper said it reduces **internal covariate shift** (layer inputs changing distribution during training). A later paper (2018, "How Does Batch Normalization Help Optimization?") showed the bigger reason is that it makes the **loss landscape smoother**, so gradients are more predictable and bigger steps are safe. Good to mention both in an interview.

#### Where to Put It

```
Dense / Conv  →  BatchNorm  →  Activation (ReLU)        # original paper
Dense / Conv  →  Activation  →  BatchNorm                # also common, often works as well
```

- Both orders are used in practice. The original (before activation) is the safer answer in an interview
- **Drop the bias** in the layer before BatchNorm (`use_bias=False` / `bias=False`), because the mean subtraction cancels it, and `β` already does the shifting
- Don't put it on the output layer

#### Problems and Limitations

- **Small batch sizes** (e.g., 1–8): batch mean/variance are noisy and unreliable → training gets worse. Use **Group Norm** or **Layer Norm** instead
- **Train/inference mismatch:** forgetting `model.eval()` in PyTorch means batch stats are used at inference → predictions change depending on batch, and running stats get corrupted
- **RNNs / variable-length sequences:** awkward to apply over time steps → Layer Norm is used instead
- **Distributed training:** each GPU sees only its own small batch → may need **SyncBatchNorm** to share statistics across GPUs
- **Fine-tuning / transfer learning:** when you freeze a pre-trained model, keep its BatchNorm layers in **inference mode** too, otherwise the running stats get overwritten by your small new dataset and accuracy drops. In Keras, setting `layer.trainable = False` on a BatchNorm layer does this automatically (TF 2.x)
- Clashes with **dropout** placed before it (variance shift — see Dropout section)

#### Normalization Types Compared

| Type | Normalizes over | Depends on batch? | Used in |
|---|---|---|---|
| **Batch Norm** | Batch (+ H, W), per feature/channel | Yes | CNNs, dense nets with decent batch size |
| **Layer Norm** | All features of **one example** | No | Transformers, RNNs |
| **Instance Norm** | H, W of one example, per channel | No | Style transfer, image generation |
| **Group Norm** | Groups of channels in one example | No | CNNs with small batches (detection, segmentation) |
| **RMSNorm** | Like Layer Norm, but only divides by root-mean-square (no mean subtraction, no β) | No | Modern LLMs (LLaMA, Mistral) — cheaper, works as well |

Easy way to remember: **BatchNorm normalizes each feature across the batch; LayerNorm normalizes each example across its features.**

#### BatchNorm From Scratch (NumPy)

```python
import numpy as np

class BatchNorm:
    def __init__(self, num_features, momentum=0.9, eps=1e-5):
        self.gamma = np.ones(num_features)
        self.beta = np.zeros(num_features)
        self.running_mean = np.zeros(num_features)
        self.running_var = np.ones(num_features)
        self.momentum, self.eps = momentum, eps

    def __call__(self, x, training=True):          # x shape: (batch, features)
        if training:
            mean, var = x.mean(axis=0), x.var(axis=0)
            self.running_mean = self.momentum * self.running_mean + (1 - self.momentum) * mean
            self.running_var = self.momentum * self.running_var + (1 - self.momentum) * var
        else:
            mean, var = self.running_mean, self.running_var
        x_hat = (x - mean) / np.sqrt(var + self.eps)
        return self.gamma * x_hat + self.beta

bn = BatchNorm(1)
x = np.array([[2.0], [4.0], [6.0], [8.0]])
print(bn(x).ravel())   # ≈ [-1.34 -0.45  0.45  1.34]
```

#### BatchNorm Interview Questions

- **What is BatchNorm?** Normalizing each layer's inputs using the mini-batch mean and variance, then applying a learnable scale (γ) and shift (β)
- **Why γ and β?** So the network isn't forced to mean 0 / variance 1; it can learn any scale, even undo the normalization
- **What's different at inference?** Uses running averages of mean/variance collected during training instead of batch stats
- **Why does it speed up training?** Allows higher learning rates and smooths the loss landscape; original paper credits reducing internal covariate shift
- **Is it a regularizer?** Mildly — batch statistics add noise. It's not a replacement for dropout/L2
- **Before or after activation?** Original paper: before. Both work in practice
- **Why drop the bias before BN?** Mean subtraction cancels it; β does the same job
- **Problem with small batches?** Noisy statistics → use Group Norm or Layer Norm
- **BatchNorm vs LayerNorm?** BatchNorm normalizes each feature across the batch; LayerNorm normalizes each example across its features, so it doesn't depend on batch size → used in Transformers
- **What do LLMs use?** LayerNorm or RMSNorm (LLaMA uses RMSNorm), usually in "pre-norm" position (before attention / feed-forward)
- **Trainable params in BN?** 2 per feature (γ, β) + 2 non-trainable (running mean, running var)
- **Fine-tuning gotcha?** Keep the pre-trained BN layers in inference mode, or the running stats get overwritten by the new small dataset

### 7. Other Techniques

- **Label Smoothing** — instead of hard targets like `[0, 1]`, use `[0.05, 0.95]`, so the model doesn't become overconfident (common in classification and Transformers)
- **Reduce model size** — fewer layers/neurons = less capacity to memorize
- **Gradient clipping** — not regularization exactly, but caps gradient size to prevent exploding gradients and unstable training
- **Ensembles** — average predictions of several models to reduce variance

### Interview One-Liners

- **What is regularization?** Anything that limits how much the model can memorize, so it generalizes better to unseen data
- **L1 vs L2?** L1 makes many weights exactly zero (sparse, feature selection); L2 keeps all weights small but non-zero
- **Why does dropout work?** Neurons can't depend on each other, and it acts like averaging many smaller networks
- **What happens to dropout at test time?** It's turned off; inverted dropout already scaled activations during training so outputs match
- **How do you know a model is overfitting?** Training loss keeps dropping while validation loss goes up
- **First thing to try for overfitting?** More data / augmentation, then dropout + weight decay + early stopping
- **Can you over-regularize?** Yes — too much regularization causes underfitting (high bias)

Hyperparameters are configuration values set **before** training begins (as opposed to weights/biases, which are **learned**).

| Hyperparameter | Description |

## Simple Implementation in Python (Keras)

Below is a simple feedforward neural network built using **TensorFlow/Keras** for a binary classification problem.

```python
import numpy as np
from tensorflow import keras
from tensorflow.keras import layers

# Sample data: X = features, y = binary labels
X = np.random.rand(1000, 10)

```

4. Compiles the model with the **Adam** optimizer and **binary cross-entropy** loss.
5. Trains the model using `.fit()`, which internally performs forward propagation, loss calculation, and backpropagation for the given number of epochs.

## Frequently Asked Questions (FAQs)

**Q1. What is the difference between a Perceptron and a Neural Network?**
A Perceptron is a single-layer, single-neuron model that can only solve linearly separable problems. A Neural Network is a network of many perceptron-like neurons arranged in multiple layers, capable of solving complex, non-linear problems.

**Q2. Why do we need activation functions?**
Activation functions introduce non-linearity into the network. Without them, stacking multiple layers would be mathematically equivalent to a single linear layer, severely limiting what the network could learn.

**Q3. What is the vanishing gradient problem?**
It occurs when gradients become extremely small as they are backpropagated through many layers, causing earlier layers to learn very slowly or stop learning altogether. It is common with Sigmoid/Tanh activations in deep networks and is mitigated using ReLU, LSTM gating, batch normalization, or residual connections.

**Q4. How many hidden layers/neurons should a network have?**
There is no fixed rule — it depends on the complexity of the problem and dataset size. It's common to start with a small architecture and increase depth/width while monitoring validation performance, using techniques like cross-validation or hyperparameter tuning.

**Q5. What is the difference between an epoch, a batch, and an iteration?**
- **Epoch** — one complete pass through the entire training dataset.
- **Batch** — a subset of the training data processed together before a weight update.
- **Iteration** — one weight update step (i.e., one batch processed).

Suppose you have 1,000 training data points
epoch = model sees all 1,000 training examples once.
```

Epoch 1 → sees all 1,000
Epoch 2 → sees all 1,000
Epoch 3 → sees all 1,000
...
Epoch 10 → sees all 1,000
```
batch = Instead of giving all 1,000 examples to the model at once, we divide them into smaller groups called batches
Total data = 1,000

```

Batch 2 → examples 101–200
Batch 3 → examples 201–300
...
Batch 10 → examples 901–1000
````
So one epoch contains 10 batches
