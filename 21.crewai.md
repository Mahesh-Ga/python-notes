# CrewAI Tutorial — What is CrewAI, Architecture, and Examples

## What is CrewAI?

**CrewAI** is a Python framework used to build **multi-agent AI systems**, where multiple AI agents work together as a **"crew"** to complete a complex task, just like a team of employees, each with a specific role, working together to finish a project.

In simple words: instead of asking one single LLM to do everything (research, write, review, summarize), CrewAI lets you create **multiple specialized agents** — each with its own role, goal, and personality — and have them **collaborate, delegate tasks, and pass work to each other** to produce a final result.

CrewAI is built around a simple, human-like idea: **real-world teams get better results through role specialization and collaboration than one person trying to do everything alone.** CrewAI brings that same structure to AI agents.

## Why do we need CrewAI?

A single LLM call, or even a single agent, struggles with complex, multi-step tasks that require different kinds of expertise. For example, writing a research report requires:

1. **Someone to research** the topic and gather facts.
2. **Someone to write** the content in a clear and structured way.
3. **Someone to review/edit** the content for quality and accuracy.

Doing all of this in one giant prompt often produces weaker results, because the LLM is trying to juggle multiple different jobs at once. CrewAI solves this by:

- Letting you define **separate agents**, each focused on one job (like a "Researcher" agent and a "Writer" agent).
- Giving each agent a **role, goal, and backstory**, which shapes how it behaves and "thinks."
- Letting agents use **tools** (web search, file reading, APIs) to do their job properly.
- Automatically **managing how tasks flow between agents**, so the output of one agent becomes the input for the next.

This makes CrewAI a natural fit for **workflow automation** tasks that map cleanly onto a team of specialists, such as content creation pipelines, research assistants, and business-process automation.

## Key Features of CrewAI

| Feature | Description |
|---|---|
| **Role-based Agents** | Each agent is defined with a role, goal, and backstory, which guides its behavior — similar to giving a job description to an employee. |
| **Tasks** | Units of work assigned to agents, with a clear description and expected output. |
| **Crew** | A group of agents and tasks working together to complete an overall objective. |
| **Process (Orchestration)** | Defines how tasks are executed — one after another (sequential) or coordinated by a manager agent (hierarchical). |
| **Tools** | Agents can be given tools (web search, file read/write, custom APIs) to actually take actions, not just talk. |
| **Memory** | Agents can remember past interactions/results, so a crew can build on earlier work instead of starting fresh each time. |
| **Delegation** | Agents can hand off work to other agents automatically, if allowed, mimicking how a real team delegates sub-tasks. |

## Core Components of CrewAI

### 1. Agent

An **Agent** is one AI worker with a specific identity: a `role`, a `goal`, and a `backstory` that shapes its personality and how it approaches its work.

```python
from crewai import Agent

researcher = Agent(
    role="Senior Research Analyst",
    goal="Find accurate and up-to-date information on the given topic",
    backstory="You are an experienced analyst who is excellent at digging up facts and verifying sources.",
    tools=[search_tool],
    verbose=True,
)
```

### 2. Task

A **Task** is a specific piece of work assigned to an agent, describing what needs to be done and what the output should look like.

```python
from crewai import Task

research_task = Task(
    description="Research the latest trends in {topic} and summarize the key findings.",
    expected_output="A bullet-point summary of the top 5 trends.",
    agent=researcher,
)
```

### 3. Crew

A **Crew** is the team — it brings together the agents and tasks, and runs them to produce the final result.

```python
from crewai import Crew

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],
    process="sequential",   # or "hierarchical"
)

result = crew.kickoff(inputs={"topic": "AI Agents"})
print(result)
```

### 4. Process

The **Process** decides how tasks are orchestrated among agents:

- **Sequential** — tasks run one after another in a fixed order, and the output of one task is passed as context into the next.
- **Hierarchical** — a "manager" agent (either defined by you or auto-created) oversees the crew, assigns tasks, and can dynamically decide which agent should do what — similar to a manager delegating work in a real team.

### 5. Tools

Agents become far more useful when they can act, not just generate text. CrewAI agents can be equipped with **tools** — such as web search, file readers, code execution, or custom API calls — so they can actually fetch real information or perform real actions instead of relying only on what the LLM already knows.

```python
from crewai_tools import SerperDevTool

search_tool = SerperDevTool()
researcher = Agent(role="Researcher", goal="...", backstory="...", tools=[search_tool])
```

## How CrewAI Works — Step by Step

1. **Define Agents** — decide what roles are needed for the task (e.g., Researcher, Writer, Editor) and create an `Agent` for each, with a role, goal, and backstory.
2. **Give Agents Tools** (optional) — attach tools like web search or file access so agents can gather real information or take real actions.
3. **Define Tasks** — write out the specific tasks that need to be done, and assign each task to the right agent.
4. **Assemble the Crew** — combine the agents and tasks into a `Crew`, and choose a process (`sequential` or `hierarchical`).
5. **Kick off the Crew** — call `crew.kickoff()` with any input variables; CrewAI runs the agents through their tasks in order (or via the manager, if hierarchical).
6. **Collect the Result** — the final output is returned once all tasks are complete.

## Example: A Simple Research-and-Write Crew

```python
from crewai import Agent, Task, Crew

# Step 1: Define Agents
researcher = Agent(
    role="Research Analyst",
    goal="Gather accurate facts about {topic}",
    backstory="An expert at finding reliable, up-to-date information.",
)

writer = Agent(
    role="Content Writer",
    goal="Write a clear, engaging summary based on research",
    backstory="A skilled writer who turns raw research into readable content.",
)

# Step 2: Define Tasks
research_task = Task(
    description="Research {topic} and list the key facts.",
    expected_output="A list of 5-6 key facts about {topic}.",
    agent=researcher,
)

writing_task = Task(
    description="Using the research provided, write a short summary article about {topic}.",
    expected_output="A 200-word article.",
    agent=writer,
    context=[research_task],   # writer receives research_task's output as context
)

# Step 3: Assemble and Run the Crew
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],
    process="sequential",
)

result = crew.kickoff(inputs={"topic": "Agentic AI"})
print(result)
```

**Flow:**
```
researcher (research_task) -> produces facts
        │
        ▼
writer (writing_task, using researcher's output as context) -> produces final article
```

## CrewAI vs LangGraph

Both are used to build multi-step, multi-agent AI systems, but they approach the problem differently.

| Aspect | CrewAI | LangGraph |
|---|---|---|
| Core idea | A **team of role-based agents** collaborating on tasks | A **graph of nodes and edges** representing control flow |
| Structure | High-level — agents, tasks, crew, process | Low-level — you define nodes, edges, and state yourself |
| Best for | Tasks that map naturally to a "team" (research → write → review) | Complex custom control flow (loops, conditional routing, retries) needing fine-grained control |
| Ease of use | Faster to set up for standard multi-agent workflows, less code | More flexible but requires more manual wiring |
| Control flow | Sequential or hierarchical processes, less granular | Full control over branching, looping, and state at every step |
| Underlying flexibility | Opinionated, higher-level abstraction | Unopinionated, lower-level building block |

**Rule of thumb:** choose **CrewAI** when the task naturally maps to a team of specialists doing a fairly standard workflow; choose **LangGraph** when you need precise, custom control over the agent's decision-making logic (loops, conditional branches, human-in-the-loop, checkpointing).

## Advantages of CrewAI

- **Quick to set up** — role-based agents and tasks map naturally to how people already think about teams and workflows.
- **Less boilerplate** than hand-building a graph — the framework handles orchestration for you.
- **Good for standard multi-agent patterns** like research-then-write, plan-then-execute, or review pipelines.
- **Tool integration** is straightforward, letting agents take real actions (search, read files, call APIs).
- **Hierarchical process** gives you manager-style delegation without writing custom routing logic.

## Disadvantages / Limitations

- **Less fine-grained control** than LangGraph — harder to express complex custom loops or conditional logic beyond what `sequential`/`hierarchical` processes offer.
- **Higher-level abstraction** can make debugging harder when something goes wrong deep inside the orchestration.
- Agent behavior depends heavily on how well the `role`/`goal`/`backstory` are written — poorly defined agents can produce inconsistent results.
- Less suited for workflows that need precise state machine behavior (e.g., pausing for human approval mid-task, resuming exactly where it left off) compared to LangGraph's built-in checkpointing.

## Real-World Applications of CrewAI

- **Content creation pipelines** — research agent + writer agent + editor agent producing blog posts or reports.
- **Market/competitive research** — multiple agents gathering and synthesizing information from different sources.
- **Customer support automation** — a triage agent routing issues to specialized agents (billing, technical, general).
- **Business process automation** — agents handling steps of a workflow that used to require multiple people (e.g., lead qualification, report generation).
- **Software development assistants** — one agent plans, another writes code, another reviews/tests it.

## Conclusion

CrewAI makes it easy to build **multi-agent AI systems** by modeling them the way real teams work: agents with roles and goals, tasks assigned to them, and a crew that orchestrates how the work flows between them. It trades some of the fine-grained control that a framework like **LangGraph** offers for a much faster, more intuitive way to set up standard multi-agent workflows — making it a great choice when your problem naturally breaks down into a team of specialists collaborating toward one outcome.
