#### The Three Building Blocks
Everything in Neo4j is built from only three things.
    - Node - An entity (person, company, city)
    - Property - Information about a thing
    - Relationship - A connection

- Just like SQL, we have cypher 

1. `NODE`: A node represents an object.
A node has:
- label (Person) 
    - One node can have multiple labels.
    ```cypher
    (:Person:Employee {
        name:"Alice"
    })
    ```
    - Alice is both Person & Employee

- properties (name and age)
    ```cypher
    (:Person {
        name: "Alice",
        age: 25
    })
    ```
    - Properties store actual data.
    - skills:["Java","Python","SQL"]

2. `Relationships`
- Unlike SQL foreign keys, this connection is stored directly.
- Relationships have
    - direction
    - type
    - properties
```cypher
(Alice)-[:FRIEND]->(Bob)
```
- **Relationship Properties**: Relationships can store information too.
```cypher
(Alice)-[:WORKS_IN {
    since:2022
}]->(IT) 
```
```dmg
               Manages
        Alice ----------> Bob 
          \          /
  WORKS_IN \       /  WORKS_IN 
            \     /
              IT
```
- This is much more natural than multiple SQL joins.

### Neo4j uses Cypher. (CQL)
```cypher
// Create
CREATE (p:Person {name: "Mahesh", role: "SWE"})

// Match + return (SELECT + WHERE)
MATCH (p:Person {name: "Mahesh"}) RETURN p

// Finding Relationships. (find people and where they work)
MATCH (p:Person)-[:WORKS_AT]->(c:Company)
RETURN p.name, c.name

// Pattern Matching
// Cypher works by drawing patterns.
// (node)-[relationship]->(node)

// Variable Length Relationships
// A -> B -> C -> D
//Find friends within 3 hops.
//SQL struggles with this. Neo4j is built for it.
MATCH (a:Person)-[:FRIEND*1..3]->(friend)
RETURN friend

// Updating Data
MATCH (p:Person {name:"Alice"})
SET p.age=26

// Delete only relationship.
MATCH (a)-[r:WORKS_IN]->(d)
DELETE r

// delete node 
MATCH (p:Person {name:"Bob"})
DELETE p

// If relationships exist: DETACH DELETE removes the node and all its relationships.
MATCH (p:Person {name:"Bob"})
DETACH DELETE p

// MERGE = "create if not exists" (idempotent upsert — critical for pipelines that re-run)
MERGE (p:Person {email: "m@x.com"})
ON CREATE SET p.created_at = timestamp()
ON MATCH SET p.last_seen = timestamp()

// Variable-length path — the thing SQL can't do cleanly
MATCH (a:Person {name: "Mahesh"})-[:KNOWS*1..3]->(b:Person)
RETURN DISTINCT b.name
```

### INDEXES
- Without indexes: Neo4j checks many nodes.
- With an index: It quickly jumps to the right node.

### Constraints
- Prevent duplicate values.
```cypher
CREATE CONSTRAINT unique_email
FOR (p:Person)
REQUIRE p.email IS UNIQUE;
```

### Shortest Path
```cypher
MATCH p=shortestPath(
    (a)-[*]->(b)
)
RETURN p
```
