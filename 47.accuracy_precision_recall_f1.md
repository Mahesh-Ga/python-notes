# Accuracy, Precision, Recall, F1 — Intuition

## Start with the confusion matrix

Every one of these metrics comes out of four numbers. Say you built a model that predicts "is this email spam?"

- **TP (True Positive):** predicted spam, actually spam
- **TN (True Negative):** predicted not spam, actually not spam
- **FP (False Positive):** predicted spam, actually not spam — you flagged a good email
- **FN (False Negative):** predicted not spam, actually spam — you let spam through

Once you have these four counts, every metric below is just a different ratio of them.

## Accuracy

**"Out of everything, how much did I get right?"**

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

This is the metric everyone reaches for first because it's the most intuitive, and it's also the one that lies to you the most.

Classic trap: 1000 emails, only 10 are actually spam. A model that just predicts "not spam" every single time gets 990/1000 = 99% accuracy while catching zero spam. Accuracy looks great, model is useless. This is why accuracy falls apart on imbalanced data — fraud detection, disease screening, spam, churn — basically anywhere the thing you care about is rare.

## Precision

Out of positive predictions donne by model, how many are correct

```
Precision = TP / (TP + FP)
```
- FP (email is spam but not actual spam) are expensive, you optimize for precision.

## Recall

Out of actual positive cases, how many model able to find. 

```
Recall = TP / (TP + FN)
```
- FN is expensive (not a cancer but actually have a cancer)

> Precision and recall pull in opposite directions. If you want to never miss spam (high recall), just flag everything as spam — recall becomes 100% but precision tanks because you're also flagging good emails. If you want to never wrongly flag a good email (high precision), only flag the emails you're dead sure about — precision goes up but you'll miss the sneakier spam, so recall drops. You can't max both by just shifting the threshold; there's a real tradeoff.

## F1 Score

**"Give me one number that punishes me if either precision or recall is bad."**

```
F1 = 2 * (Precision * Recall) / (Precision + Recall)
```

It's the harmonic mean, not the plain average, and that choice matters. Harmonic mean is dragged down hard by the smaller of the two values. So if precision is 0.9 but recall is 0.1, a normal average would say 0.5, which sounds okay — but F1 gives you about 0.18, which correctly tells you the model is bad. F1 refuses to let one strong number hide one weak number.

Use F1 when you care about both false positives and false negatives roughly equally and want a single number to compare models — for example when tuning a threshold or comparing two models on an imbalanced dataset where accuracy would mislead you.

High Precision: -> few FPs  (few wrongly identified) 
High Recall: -> Few FNs (few wrongly not identified)


TPR — True Positive Rate (Recall) - how many actual positive cases your model successfully catches. - TP / (TP + FN)
FPR — False Positive Rate - how many actual negative cases your model incorrectly catches as positive. - FP / (FP + TN)

wants high TPR and low FPR.

## Micro F1 vs Macro F1: Useful in multi class 

Both turn per-class F1 into one number when you have more than two classes (multi-class or multi-label).

- **Macro F1:** compute F1 for each class separately, then take a plain average. Every class counts equally.
- **Micro F1:** add up TP, FP and FN across all classes first, then compute one F1 from those totals. Every sample counts equally, so big classes dominate.

```
F1 (one class) = 2TP / (2TP + FP + FN)

Macro F1 = (F1_class1 + F1_class2 + ... + F1_classN) / N

P_micro  = ΣTP / (ΣTP + ΣFP)
R_micro  = ΣTP / (ΣTP + ΣFN)
F1_micro = 2 * P_micro * R_micro / (P_micro + R_micro)
```

Example with imbalanced classes:

| Class | Samples | TP | FP | FN | F1 |
|---|---|---|---|---|---|
| A | 900 | 880 | 40 | 20 | 0.967 |
| B | 80 | 40 | 20 | 40 | 0.571 |
| C | 20 | 4 | 6 | 16 | 0.267 |

- Macro F1 = (0.967 + 0.571 + 0.267) / 3 ≈ **0.60**
- Micro: ΣTP = 924, ΣFP = 66, ΣFN = 76, so P = 0.933, R = 0.924, F1 ≈ **0.93**

Micro looks great because class A is 90% of the data and it does well. Macro shows that B and C are doing badly.

| | Micro F1 | Macro F1 |
|---|---|---|
| How it averages | Pools all predictions, then one F1 | Averages per-class F1 scores |
| Each class weighted | By its size | Equally |
| Affected by imbalance | Yes, large classes dominate | No, rare classes matter as much as common ones |
| Weakness | Hides poor performance on small classes | A tiny noisy class can swing the score a lot |

Things to remember:
- In single-label multi-class classification, Micro F1 = accuracy. Each wrong prediction is one FP for one class and one FN for another, so P_micro = R_micro = accuracy.
- **Weighted F1** is a third option: a macro-style average, but each class is weighted by its support. It sits between the two.
- If the classes are balanced, micro and macro come out close.

When to use which:
- Balanced classes: either one.
- Imbalanced, and rare classes matter (fraud, disease, rare intents): macro.
- Imbalanced, and overall per-sample correctness is the goal: micro.

Interview answer: Macro F1 averages the F1 of each class, so every class counts the same and weak performance on rare classes shows up. Micro F1 pools all the TP, FP and FN first, so big classes dominate, and for single-label problems it equals accuracy. With imbalanced data I'd report macro F1 along with the per-class scores, because micro can look good while a small class fails.

## ROC stands for Receiver Operating Characteristic.
- Remember that the threshold determines which emails are classified as spam
- The ROC curve plots TPR and FPR values for every possible threshold.

## AUC 
- AUC means Area Under the ROC Curve.
- An AUC of 0.85 generally indicates better **classifier** than an AUC of 0.65.
