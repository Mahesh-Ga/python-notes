# Accuracy, Precision, Recall, F1 — Intuition

## Start with the confusion matrix

Every one of these metrics comes out of four numbers. Say you built a model that predicts "is this email spam?"

- **TP (True Positive):** predicted spam, actually spam
- **TN (True Negative):** predicted not spam, actually not spam
- **FP (False Positive):** predicted spam, actually not spam — you flagged a good email
- **FN (False Negative):** predicted not spam, actually spam — you let spam through

Once you have these four counts, every metric below is just a different ratio of them.

## Accuracy

**"Out of everything, how much did I get right?"**

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```

This is the metric everyone reaches for first because it's the most intuitive, and it's also the one that lies to you the most.

Classic trap: 1000 emails, only 10 are actually spam. A model that just predicts "not spam" every single time gets 990/1000 = 99% accuracy while catching zero spam. Accuracy looks great, model is useless. This is why accuracy falls apart on imbalanced data — fraud detection, disease screening, spam, churn — basically anywhere the thing you care about is rare.

## Precision

**"When I said yes, how often was I right?"**

Precision is the fraction of predicted positive cases that are actually positive.

```
Precision = TP / (TP + FP)
```

It only looks at what you predicted positive, and asks how much of that was actually correct. High precision means few FPs.

Think of it from the cost-of-a-false-positive angle. If your spam filter has low precision, it keeps marking real emails (like a job offer) as spam and hiding them from you — that's annoying and costly. So when false positives are expensive, you optimize for precision.

## Recall

**"Out of everything that was `actually` yes, how many did I catch?"**

Recall is the fraction of actual positive cases that the model successfully identified.

```
Recall = TP / (TP + FN)
```

This one only looks at the actual positives and asks how many you found. High recall means you rarely miss the real thing.

Now think of it from the cost-of-a-false-negative angle. If you're screening for cancer and your model has low recall, it's telling sick patients they're fine — that's the dangerous kind of mistake. So when missing a positive is the expensive mistake, you optimize for recall.

> Precision and recall pull in opposite directions. If you want to never miss spam (high recall), just flag everything as spam — recall becomes 100% but precision tanks because you're also flagging good emails. If you want to never wrongly flag a good email (high precision), only flag the emails you're dead sure about — precision goes up but you'll miss the sneakier spam, so recall drops. You can't max both by just shifting the threshold; there's a real tradeoff.

## F1 Score

**"Give me one number that punishes me if either precision or recall is bad."**

```
F1 = 2 * (Precision * Recall) / (Precision + Recall)
```

It's the harmonic mean, not the plain average, and that choice matters. Harmonic mean is dragged down hard by the smaller of the two values. So if precision is 0.9 but recall is 0.1, a normal average would say 0.5, which sounds okay — but F1 gives you about 0.18, which correctly tells you the model is bad. F1 refuses to let one strong number hide one weak number.

Use F1 when you care about both false positives and false negatives roughly equally and want a single number to compare models — for example when tuning a threshold or comparing two models on an imbalanced dataset where accuracy would mislead you.

High Precision: -> few FPs  (few wrongly identified) 
High Recall: -> Few FNs (few wrongly not identified)

## Quick way to keep them straight

- Accuracy: overall correctness, misleading when classes are imbalanced
- Precision: trustworthiness of your positive predictions (avoid FPs)
- Recall: completeness of catching actual positives (avoid missing cases)
- F1: balances precision and recall into one number, punishes imbalance between the two

## Picking the right one for the job

- Spam filter that shouldn't eat real emails → precision matters more
- Cancer/fraud screening where missing a case is dangerous → recall matters more
- Balanced classes, no lopsided cost between the two error types → accuracy is fine
- Need one number to rank models on an imbalanced problem → F1 (or precision-recall curve / AUC-PR if you want the full picture across thresholds)
