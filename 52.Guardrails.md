What "guardrails" means here

In an LLM app, like a RAG pipeline or chatbot, you don't want to trust the model or the user blindly. Guardrails are checks that run before the request reaches the model and after the model responds:


> User input → [input guardrails] → LLM / retrieval → [output guardrails] → User

Typical checks:
- Is this user allowed to ask this, or to see these documents?
- Does the input contain PII (names, phone numbers, Aadhaar/SSN, emails, card numbers)?
- Is the prompt trying to jailbreak or inject instructions?
- Does the output leak confidential data, or break company policy?

### "Policy chains"

A policy chain is a series of rules applied one after another, where each one can allow, block, or modify the request. For example:

1. Auth check: does the user have the "legal-team" role?
2. Data access: can this role read documents tagged "confidential"?
3. PII redaction: mask personal data in the prompt.(hiding or replacing sensitive information—like names, phone numbers, or ID numbers—with fake or blurred placeholders before sending it to an AI model)
4. Output filter: block the response if it contains restricted content.
If any step fails, the request stops or gets changed. It's the same idea as middleware in a web app.


#### OPA / Gatekeeper

- OPA (Open Policy Agent) is a general policy engine. You write rules in a language called Rego, and your app asks OPA "is this allowed?" It answers yes or no, plus a reason. This keeps policy logic out of your application code.

```rego
package rag.access

default allow = false

allow {
    input.user.role == "legal"
    input.document.classification != "restricted"
}
```
Your Python service sends {user, document} to OPA before retrieving or returning a document.
- Gatekeeper is OPA built into Kubernetes. It enforces policies on the cluster itself, not on the LLM requests. Examples: "every pod must have resource limits", "no containers from untrusted registries", "the LLM service must not run as root". So it guards your deployment, while plain OPA guards your application logic


#### Presidio (PII redaction) (Personal Indentifiable INformation) 

Microsoft Presidio is an open-source library that finds and masks PII in text. It has two parts:
- Analyzer: detects entities (PERSON, PHONE_NUMBER, EMAIL, CREDIT_CARD, and so on) using regex, NER models and context words.
- Anonymizer: replaces what it found by masking, hashing or swapping in fake values.
```python
from presidio_analyzer import AnalyzerEngine
from presidio_anonymizer import AnonymizerEngine

text = "Contact Ravi Kumar at ravi@abc.com or 9876543210"
results = AnalyzerEngine().analyze(text=text, language="en")
print(AnonymizerEngine().anonymize(text=text, analyzer_results=results).text)
# Contact <PERSON> at <EMAIL_ADDRESS> or <PHONE_NUMBER>
```
