## What is an Embedding?

An **Embedding** is a way of representing a piece of data — a word, sentence, image, or any other object — as a **dense vector of real numbers** (e.g., 384, 768, or 1536 numbers) in a continuous vector space, such that objects with **similar meaning end up close together** in that space.

In simple words: an embedding converts something a computer can't directly reason about (text, images, audio) into a list of numbers that captures its **meaning**, not just its raw form — so that "king" and "queen" end up near each other in vector space, while "king" and "banana" end up far apart.

```
"king"   → [0.21, -0.53, 0.88, ..., 0.10]   (e.g., 768 numbers)
"queen"  → [0.19, -0.49, 0.91, ..., 0.12]   (close to "king")
"banana" → [-0.71, 0.44, -0.02, ..., 0.65]  (far from "king")
```

---

## Why do we need Embeddings?

Computers understand numbers, not words or images directly. A naive approach — assigning each word a random ID (`"cat"` → 42, `"dog"` → 43) — fails because:

- **No notion of similarity**: ID 42 and ID 43 are just as "different" as ID 42 and ID 9999, even though "cat" and "dog" are semantically related.
- **No generalization**: A model trained on "I love cats" doesn't automatically know anything about "I love dogs".

Embeddings solve this by placing every object in a **shared vector space** where **geometric distance reflects semantic similarity**. This lets machine learning models compare, cluster, search, and reason about meaning using simple math (like distance and angle between vectors) instead of exact string matching.

---

## Real-World Analogy

Think of embeddings like **coordinates on a map**. Two cities that are close in real life have coordinates that are close together on the map. Embeddings do the same thing, but instead of physical location, the "closeness" represents **semantic meaning** — cities become words, sentences, images, or products, and the "map" has hundreds or thousands of dimensions instead of just 2.

## How are Embeddings Created?

Embeddings are produced by a trained **embedding model** (a neural network) that learns, from large amounts of data, to map raw input into vectors such that similar inputs land close together.

```
Raw Input (text/image/audio) → Embedding Model → Dense Vector (embedding)
```

| Data Type | Example Embedding Models |
|---|---|
| **Text** | Word2Vec, GloVe, BERT, OpenAI `text-embedding-3`, Sentence-BERT |
| **Image** | CLIP, ResNet feature vectors |
| **Audio** | Wav2Vec |
| **Multimodal (text+image)** | CLIP, ImageBind |

```python
# Conceptual example using OpenAI embeddings
from openai import OpenAI

client = OpenAI()
response = client.embeddings.create(
    model="text-embedding-3-small",
    input="Neural networks are powerful"
)
vector = response.data[0].embedding
print(len(vector))   # e.g., 1536
```

## Types of Text Embeddings

| Type | Description | Example Models |
|---|---|---|
| **Word Embeddings** | One fixed vector per word, regardless of context | Word2Vec, GloVe |
| **Contextual Embeddings** | Vector depends on surrounding words — same word gets different vectors in different sentences | BERT, GPT |
| **Sentence/Document Embeddings** | A single vector representing an entire sentence or document | Sentence-BERT, OpenAI `text-embedding-3` |

**Example of context-sensitivity:**
> "I sat on the river **bank**." vs "I deposited money in the **bank**."

A plain word embedding (Word2Vec) gives `"bank"` the *same* vector in both sentences. A contextual embedding (BERT) gives `"bank"` *different* vectors, because it looks at the surrounding words to disambiguate meaning.

## How Similarity is Measured

Once data is converted into vectors, "how similar are two things?" becomes a **geometry problem**. The most common similarity metrics are:

| Metric | Formula | Intuition |
|---|---|---|
| **Cosine Similarity** | `(A · B) / (‖A‖ ‖B‖)` | Measures the **angle** between two vectors; ignores magnitude. Most popular for embeddings. |
| **Euclidean Distance** | `√Σ(Aᵢ - Bᵢ)²` | Measures **straight-line distance** between two points. |
| **Dot Product** | `A · B` | Similar to cosine but also influenced by vector magnitude. |

```python
import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

vec_king  = np.array([0.21, -0.53, 0.88])
vec_queen = np.array([0.19, -0.49, 0.91])
vec_banana = np.array([-0.71, 0.44, -0.02])

print(cosine_similarity(vec_king, vec_queen))   # high, e.g. 0.98
print(cosine_similarity(vec_king, vec_banana))  # low, e.g. 0.10
```

Cosine similarity ranges from **-1 to 1**: `1` means the vectors point in the same direction (very similar), `0` means unrelated, and `-1` means opposite meaning.

## The Classic Example: Vector Arithmetic

A famous demonstration from Word2Vec is that embeddings capture **relationships**, not just similarity, so you can do arithmetic on meaning:

```
vector("King") - vector("Man") + vector("Woman") ≈ vector("Queen")
```

This works because the *direction* from "Man" to "King" (royalty) is roughly the same as the direction from "Woman" to "Queen" — the model has learned the abstract concept of "royalty" as a direction in vector space, independent of gender.

## Where Embeddings are Used

| Use Case | How Embeddings Help |
|---|---|
| **Semantic Search** | Find documents by meaning, not just keyword overlap |
| **Retrieval-Augmented Generation (RAG)** | Retrieve relevant chunks from a vector database to feed into an LLM prompt (see `15.RAG.md`) |
| **Recommendation Systems** | Represent users/items as vectors; recommend items close to a user's embedding |
| **Clustering & Classification** | Group similar items using distance between embeddings |
| **Deduplication** | Detect near-duplicate text/images by checking if embeddings are extremely close |
| **Inside LLMs** | Convert token IDs into dense vectors before they enter Transformer blocks (see `28.llm_architecture.md`) |
| **Anomaly Detection** | Points far from all clusters in embedding space are flagged as outliers |

## Embeddings and Vector Databases

Because embeddings are just lists of numbers, storing and searching millions of them efficiently needs specialized storage — a **Vector Database** (e.g., Pinecone, Weaviate, Milvus, Chroma, FAISS, pgvector). These databases index vectors so that, given a query vector, they can quickly find the **k-nearest neighbors** (the most similar stored vectors) without comparing against every single item one by one.

```
User Query → Embed query → Search Vector DB (kNN) → Return top-k similar vectors → Use as context
```

This pipeline (embed → store → search) is the backbone of **semantic search** and **RAG** systems.

## Word Embeddings: Word2Vec vs GloVe vs Contextual Models

| Model | Approach | Limitation |
|---|---|---|
| **Word2Vec** (2013) | Predicts a word from its neighbors (CBOW) or neighbors from a word (Skip-gram) using a shallow neural network | One fixed vector per word — can't handle polysemy (multiple meanings) |
| **GloVe** (2014) | Learns vectors from global word co-occurrence statistics across a corpus | Same limitation — still one vector per word |
| **BERT / Transformer-based** (2018+) | Generates a vector for a word **based on its context** in the sentence | Handles polysemy correctly; more compute-intensive |

## Embedding Dimensionality

The **dimension** of an embedding is the length of the vector (e.g., 384, 768, 1536, 3072). 
3 * 2^7, 3 * 2^8, 3 * 2^9, 3 * 2^10  
- They are divisible by many powers of 2 — good for GPU parallelism.
- They are multiples of 3 — sometimes useful for attention heads.
- They double cleanly — easy to scale model size.

It's a trade-off:

| Higher Dimensions | Lower Dimensions |
|---|---|
| Capture more nuance/information | Faster to compute & compare |
| More storage & memory needed | Less storage & memory needed |
| Slower similarity search at scale | Faster similarity search at scale |
| Risk of overfitting on small datasets | May lose subtle semantic distinctions |

Choosing embedding size is a balance between **accuracy** and **efficiency/cost**, especially important when storing millions of vectors in a vector database.

---

## Quick Recap

- An **embedding** is a dense numeric vector representing the meaning of some data (text, image, audio).
- Similar things get **similar (close) vectors**; dissimilar things get **distant vectors**.
- **Cosine similarity** is the most common way to compare embeddings.
- Embeddings power **semantic search, RAG, recommendations, clustering,** and are also the **first step inside every LLM** (turning token IDs into meaningful vectors before self-attention).
- **Contextual embeddings** (BERT-style) beat classic **static word embeddings** (Word2Vec/GloVe) because they account for surrounding context.
