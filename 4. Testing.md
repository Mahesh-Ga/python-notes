### PyTest
- `pytest` command to run the test 
- pytest automatically discovers
    - File: test_*.py or *_test.py
    - Function: test_*
    - Class: Test*

```python calculator.py

```
```python tests/test_calculator.py
from calculator import add

```


#### Understand `yield` in Python:
- The `yield` keyword turns a function into a **function generator**. 
- The function generator returns an iterator.
- Unlike the return keyword which stops further execution of the function, the yield keyword returns the result so far, and continues to the next step.
```python
y = 0
def myFunc():
  global y
  y = 10
  yield "Hello"
  y = 20
  yield 51

x = myFunc() # Generator Object (will not run the function)
print("Y ", y) # => o 
for z in x: 
    print("Y", y)
    print("Return ", z)
# OUTPUT: 
# Y 10
# Return  Hello
# Y 20
# Return  51
``` 

- real project uses yield fixtures for things like database connections, temporary files, web servers, and API clients.

#### Fixture with Cleanup (yield)
Think of a yield fixture as a function with two phases:
- Setup — runs before the test.
- Cleanup — runs after the test, even if the test fails.
```python
import pytest

@pytest.fixture
def db():
    # --- SETUP ---
    print("\n[SETUP] Connecting to DB")
    conn = sqlite3.connect(":memory:") # in-memory DB for test

    yield conn # give connection to the test

    # --- CLEANUP ---
    print("[TEARDOWN] Closing DB")
    conn.close()

def test_user_exists(db):
    cursor = db.cursor()
    cursor.execute("SELECT name FROM users WHERE id=1")
    result = cursor.fetchone()
    assert result[0] == "Mahesh"
```
The yield line splits the fixture into two parts.
Before yield → Setup
At yield → Give the value to the test
After yield → Cleanup

#### Parametrization
Instead of writing three tests:

```python
import pytest
```

#### Mocking
- Suppose your function calls an API.
- Tests should not depend on external services.
- So we replace the real call with a fake one. This is called **mocking**.

`unittest.mock` - Python's built-in mocking library.
1. Mocking http call 
- `@patch("requests.get")` - Temporarily replace `requests.get` with a mock object while this test runs.
```python 
import requests

def get_user():
    response = requests.get("https://api.example.com/user")
    return response.json()

from unittest.mock import patch

@patch("requests.get")
def test_get_user(mock_get):
    mock_get.return_value.json.return_value = {
        "name":"Mahesh"
    }

    assert get_user()["name"]=="Mahesh"
```

2. Mocking Database Calls

```python
def save_user(db,user):
    db.insert(user)

from unittest.mock import Mock

def test_save():
    fake_db = Mock()
    save_user(fake_db,"Mahesh")
    fake_db.insert.assert_called_once_with("Mahesh") # PASS
```

3. Mocking an LLM API
```python
app.py
from openai import OpenAI

client = OpenAI()

def summarize(text):
    response = client.responses.create(
        model="gpt-4.1",
        input=text
    )
    return response.output_text

test.py
from unittest.mock import patch

@patch("app.client.responses.create")
def test_summary(mock_create):
    mock_create.return_value.output_text="Short summary"

    assert summarize("Very long text")=="Short summary"
```

#### Verifying Calls
Mock objects remember interactions.
```python 
from unittest.mock import Mock

mock = Mock()
mock.send_email("hi@example.com", "Hello")
mock.send_email.assert_called_once() # PASS - we called it once
mock.send_email.assert_called() # PASS
mock.delete_user.assert_not_called() # PASS - we never called delete_user
mock.send_email.assert_called_with("hi@example.com", "Hello") #PASS 
mock.send_email.assert_called_with("wrong@example.com", "Hello") # FAIL
```
