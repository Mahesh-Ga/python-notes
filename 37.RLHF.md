# RLHF — Reinforcement Learning from Human Feedback

> Companion to `28.llm_architecture.md` (base model architecture) and `26.types_of_neural_networks.md` (RL background). This note covers *why* RLHF exists, the 3-stage pipeline, the math of the reward model and PPO step, and the newer alternatives (DPO, RLAIF, KTO) that are replacing classic PPO-RLHF in practice.

---

## 1. Why RLHF exists

A base (pretrained) LLM is only trained to predict the next token over internet text. That objective does not know:

- What a *helpful* answer looks like vs. a technically-plausible-but-useless one.
- What is *harmful, biased, or unsafe* to say.
- How a *human* would rank two different responses to the same prompt.

Supervised Fine-Tuning (SFT) on curated (prompt, ideal-response) pairs helps, but it only teaches the model to imitate a fixed set of demonstrations. It cannot teach *relative preference* ("response A is better than response B") because that signal doesn't come in demonstration form — it comes as a comparison. RLHF exists to inject exactly that comparison signal into the model's weights.

**Core idea:** turn "humans prefer A over B" into a scalar reward function, then use reinforcement learning to push the LLM's policy (its token-generation behavior) toward outputs that score high on that reward — without drifting so far from the original model that it becomes incoherent or degenerate.

## 2. The 3-stage pipeline

```
┌───────────────────┐     ┌────────────────────┐     ┌──────────────────────────┐
│  Stage 1: SFT       │     │  Stage 2: Reward     │     │  Stage 3: RL Fine-tuning   │
│                     │     │  Model (RM)          │     │  (PPO)                    │
│  Pretrained LLM     │────▶│  Train RM on human   │────▶│  Optimize SFT policy       │
│  + curated          │     │  preference pairs     │     │  against RM, with a KL     │
│  (prompt, response) │     │  (A vs B rankings)     │     │  penalty back to SFT       │
│  demonstrations     │     │                       │     │  model                    │
└───────────────────┘     └────────────────────┘     └──────────────────────────┘
     "imitation"                "learn to score"           "optimize against the score"
```

### Stage 1 — Supervised Fine-Tuning (SFT)
Human labelers write high-quality (prompt → ideal response) pairs, or curate the best of several model samples. The pretrained base model is fine-tuned on these with plain next-token cross-entropy loss. Output: a model that already behaves roughly like an assistant. This is also the model everything downstream is measured against and regularized toward.

### Stage 2 — Reward Model (RM) training
1. Sample multiple responses (`y1, y2, ..., yk`) from the SFT model for the same prompt `x`.
2. Human labelers **rank** these responses (pairwise or full ranking) — ranking is much easier and more consistent for humans than assigning an absolute score.
3. Train a reward model `r_φ(x, y)` — usually the SFT model itself with the LM head swapped for a scalar-output head — to predict a score consistent with the human ranking.

**Loss — Bradley-Terry pairwise model.** For a chosen response `y_w` ("winner") and rejected response `y_l` ("loser") for the same prompt `x`:

```
loss(φ) = -log( σ( r_φ(x, y_w) - r_φ(x, y_l) ) )
```

where `σ` is the sigmoid. This just says: push the reward gap `r(y_w) - r(y_l)` to be large and positive. The RM never needs to output a calibrated absolute score — only a correctly *ordered* one.

### Stage 3 — RL fine-tuning (PPO)
Now the SFT model becomes a "policy" `π_θ` that we optimize with reinforcement learning, using the frozen reward model as the reward signal.

**Objective (per generated response `y` to prompt `x`):**

```
objective(θ) = E[ r_φ(x, y) ]  -  β · KL( π_θ(y|x) || π_SFT(y|x) )
```

- `r_φ(x, y)` — the reward-model score, pushes the policy toward high-reward text.
- `β · KL(...)` — a penalty for drifting too far from the original SFT policy in token-distribution space.
- `β` is a tunable coefficient — too small → reward hacking / gibberish that fools the RM; too large → the policy barely moves and RLHF has no effect.

PPO (Proximal Policy Optimization) is used as the RL algorithm because it clips the policy update so a single batch can't push the weights too far in one step — important here because the "environment" (the reward model) is itself an imperfect, learned approximation of human preference, not ground truth.

```
┌────────────┐   generate y   ┌────────────┐
│  Policy π_θ │ ─────────────▶ │  Reward Model│──▶ r_φ(x,y)
│ (being      │                │  (frozen)    │
│  trained)   │◀────────────── │              │
└────────────┘  PPO gradient   └────────────┘
       │           update
       └── KL penalty vs frozen π_SFT copy
```

## 3. Why not just supervise on the ranking directly?

Because the ranking data only tells you "A > B" for the *specific samples you happened to generate*. RL lets the model explore new outputs beyond that fixed sample set and get rewarded/penalized on them via the learned reward model, which generalizes the preference signal to a much larger space of possible completions than the labelers ever manually ranked.

---

## 4. Problems with classic PPO-RLHF

| Problem | What happens | Why |
|---|---|---|
| **Reward hacking / over-optimization** | Model finds outputs the RM scores highly but humans find bad (sycophantic, repetitive, verbose "safe-sounding" filler) | RM is a *proxy* for human preference, not preference itself — Goodhart's Law: "when a measure becomes a target, it ceases to be a good measure" |
| **Mode collapse** | Model converges to a narrow style of response (always hedging, always listing 3 bullet points) | RL optimization pressure rewards whatever pattern scores well on average across the RM, flattening diversity |
| **Training instability** | PPO has many moving pieces (policy, value/critic model, reward model, reference model) — 4 models in memory at once, sensitive to hyperparameters | RL is inherently higher-variance than supervised learning; needs careful reward normalization, KL tuning, value-function baselines |
| **Expensive** | Needs a value/critic network the same size as the policy, plus rollout sampling at every step | Actor-critic RL is compute- and infra-heavy compared to a single forward/backward pass of supervised loss |
| **RM ceiling** | Policy can only get as good as the RM's judgment — if the RM has blind spots or biases, the policy inherits and often amplifies them | The optimizer will find and exploit any gap between RM score and true human preference |

## 5. Alternatives that replaced/simplified PPO-RLHF

### DPO — Direct Preference Optimization
Key insight: the RL step with a KL-constrained reward objective has a **closed-form optimal policy** in terms of the reward function. Substituting that back into the Bradley-Terry loss lets you skip training a separate reward model *and* skip RL entirely — you optimize the policy directly on the same (chosen, rejected) preference pairs with a supervised-style loss:

```
loss(θ) = -log σ( β · [ log(π_θ(y_w|x)/π_ref(y_w|x)) − log(π_θ(y_l|x)/π_ref(y_l|x)) ] )
```

- No reward model, no PPO, no value network — just one policy network and a frozen reference copy of it (`π_ref`, usually the SFT model).
- Much simpler and more stable to train; became the default for most open-source alignment recipes (Zephyr, most Llama/Mistral fine-tunes) because it needs far less infrastructure than PPO.
- Trade-off: it's fully offline on a fixed preference dataset — it can't explore new generations the way online PPO can, so it's more sample-bound to what's in the preference dataset.

### RLAIF — RL from AI Feedback
Same pipeline as RLHF, but an LLM (not a human) generates the preference labels ("Constitutional AI" from Anthropic is the canonical example: a model critiques and revises its own outputs against a written set of principles, and that AI-generated preference data trains the RM). Massively cuts labeling cost; works well when the base model is already capable enough to judge quality reasonably, at the cost of inheriting/amplifying whatever biases the judge model has.

### KTO — Kahneman-Tversky Optimization
Doesn't need *paired* comparisons at all — just a binary "this output was good / bad" label per example (much cheaper/more available than pairwise rankings). Based on prospect theory (humans weigh losses more than equivalent gains); useful when you only have thumbs-up/thumbs-down signals rather than ranked pairs.

### IPO — Identity Preference Optimization
A tweak to DPO's loss to fix its tendency to overfit / push probabilities to extremes on preference pairs that are only weakly distinguishable; adds a regularization term that keeps the optimization better-calibrated.

## 6. Comparison table

| Method | Needs reward model? | Needs RL/PPO? | Data format | Stability | Compute cost |
|---|---|---|---|---|---|
| **SFT** | No | No | (prompt, ideal response) | High | Low |
| **RLHF (PPO)** | Yes | Yes | pairwise/ranked preferences | Low (many moving parts) | High (4 models) |
| **DPO** | No | No | pairwise preferences (chosen, rejected) | High | Medium (2 models) |
| **RLAIF** | Yes (AI-labeled) | Optional (often PPO or DPO downstream) | AI-generated preferences | Same as underlying RL method | Low labeling cost, same training cost |
| **KTO** | No | No | binary good/bad labels | High | Medium (2 models) |

## 7. End-to-end mental model

```
Pretraining (next-token prediction on raw text)
        │
        ▼
SFT (imitate curated ideal demonstrations)
        │
        ▼
Preference alignment  ──┬── RLHF: train RM → PPO against RM (+ KL to SFT)
  (this is "RLHF" in    ├── DPO: skip RM, optimize policy directly on preference pairs
   the broad sense)     └── RLAIF: same as above, but preferences come from an AI judge, not humans
        │
        ▼
Aligned / "chat" model (what ships as e.g. an assistant)
```

**One-line interview answer:** *"RLHF fine-tunes an already-instruction-tuned LLM by first training a reward model on human pairwise preference rankings (Bradley-Terry loss), then using PPO to optimize the LLM's policy against that reward model, with a KL penalty back to the SFT model to prevent reward hacking and degenerate outputs. In practice, many teams now use DPO instead, which achieves the same alignment goal by folding the reward model and RL step into a single closed-form supervised loss directly on the preference pairs."*
