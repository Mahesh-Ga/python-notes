- WSGI is the older Python web standard used by Flask and Django (traditional).
- ASGI is the newer standard used by FastAPI, Starlette, and modern Django async features.
- In production, you don't run python app.py. You run an ASGI/WSGI server like uvicorn or gunicorn that manages worker processes and handles real traffic.

#### WSGI: (Web Server Gateway Interface) 
- The browser sends an HTTP request.
- Gunicorn receives it and passes it to Flask through the WSGI interface.
- Flask processes the request and returns a response.

- Worker cannot process another request while waiting.
- Even though the CPU is mostly idle, that worker is blocked.
- This is called **synchronous (blocking) execution**.
- request waits until one worker becomes free.
- More traffic → need more workers.
- More workers → more RAM.
- Used by Flask
- Gunicorn Server (Sync)

#### ASGI: (Asynchronous Server Gateway Interface)
- It supports:
    - async functions
    - WebSockets
    - long-lived connections
    - high concurrency
- Used by: FastAPI (Major Difference between Flask and FastAPI)
- Instead of waiting for next request to serve in worker, ASGI will keep all requests in waiting simultaneously.
- One process can manage hundreds or thousands of waiting connections.
- **Event Loop:** 
    - each worker process has its own event loop
    - each event loop handles many concurrent requests
    - Instead of sitting idle while one request waits, others continue.
    - it keeps checking:
        Has DB replied?
        Has Redis replied?
        Has API replied?
    - When one finishes, it resumes that request.
    - it maintains all the statuses related to that waiting connection 
- **Best for I/O-bound work:** 
    - These spend most of their time waiting.
    - ASGI uses that waiting time to serve other requests.
- ASGI improves concurrency for I/O-bound tasks, not CPU-bound computation.
- Uvicorn Server (ASync) 


### Gunicorn + Uvicorn together

A common production command is:
```bash
gunicorn main:app -k uvicorn.workers.UvicornWorker --workers 4
```
- Gunicorn manages worker processes.
- Each worker runs Uvicorn.
- Each Uvicorn worker runs an ASGI event loop.
